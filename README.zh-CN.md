# Claude of Duty

获取更新 [在此](https://shumer.dev/newsletter)。

一款基于 Three.js r180 和 WebGL2 构建的浏览器第一人称射击游戏。约
5.5 万行代码，横跨 11 个子系统，由一支 AI 代理舰队在编排下编写完成。

**没有任何美术资产。** 每一张纹理、每一个网格、每一段动画、每一段音效都在加载时
从代码程序化生成。没有模型、没有 HDR 环境贴图、没有图片文件、没有音频文件。
唯一的运行时依赖是 `three`。

```bash
npm install
npm run dev          # http://127.0.0.1:5173
```

点击画布锁定鼠标。WASD 移动、鼠标瞄准、左键开火、右键瞄准镜（ADS）、
R 换弹、Shift 冲刺、Ctrl 下蹲、空格跳跃、Q/E 侧身、Esc 释放鼠标。

## 项目内容

| 子系统 | 功能 |
|---|---|
| `render` | HDR 管线，基于 `sampler2DArray` 的级联阴影贴图（含像素对齐和 PCSS 接触硬化）、MRT 深度/法线/速度预通道、GTAO、带 YCoCg 方差裁剪的 TAA、瓦片扩张运动模糊、Karis 泛光金字塔、GPU EV100 测光、程序化 33³ 调色 LUT、AgX 合成 |
| `materials` | GPU 纹理熔炉：19 种程序化表面（混凝土、砖、灰泥、沥青、沙地、锈蚀/喷漆/拉丝金属、木材、织物、麻布、玻璃……），周期噪声保证无缝平铺，Sobel 高度→法线、视差遮蔽映射、三平面投影、曲率驱动的边缘磨损 |
| `sky` | 大气散射、昼夜循环、PMREM 环境贴图生成、体积雾和光轴 |
| `world` | 约 120×120 m 的市集街道：模块化建筑套件（真实墙体厚度、可进入室内）、数百个实例化道具 |
| `physics` | 从零手写，无第三方库。分箱 SAH BVH（29k 三角形 → 22 ms 建树 14k 节点，0.25 µs/次射线检测）、带 5 平面褶皱栈的扫掠胶囊体角色控制器、带 CCD 的冲量刚体、PBD 布娃娃、多层子弹穿透 |
| `player` | 移动状态机、滑铲/翻越/侧身、镜头手感 |
| `weapons` | 程序化武器几何、第一人称模型骨架、ADS、弹簧后坐力、程序化换弹、带飞行时间和下坠的弹道 |
| `fx` | GPU 粒子、贴花、曳光弹、枪口闪光、爆炸 |
| `ai` | 蒙皮士兵、导航网格寻路、感知、掩体行为、布娃娃死亡 |
| `ui` | DOM/CSS HUD：准星、命中标记、小地图、指南针、击杀信息 |
| `audio` | Web Audio 合成——无声音文件。分层枪声、卷积混响、HRTF 空间化、遮挡 |

`ARCHITECTURE.md` 是各代理协作时依据的契约：子系统接口、
目录归属、跨子系统事件词汇表，以及共享表面类型。

## 工具链

这个仓库真正有意思的部分，与其说是游戏，不如说是这套工具链。

| 工具 | 用途 |
|---|---|
| `tools/capture.mjs` | 通过 GPU 驱动的无头 Chromium 对指定镜头截图 |
| `tools/shotset.mjs` | 一次会话内完成全部 11 个镜头——快速评审集 |
| `tools/baseline.mjs` | **可复现**截图：每个镜头在独立页面、固定帧预算下运行。多次运行逐位一致 |
| `tools/imagediff.mjs` | 逐像素门禁。任一像素变化即非零退出 |
| `tools/profile.mjs` | 在真实设备像素比下运行的游戏性能分析器。帧时间*分布*，以及通过逐帧 WebGL 程序数进行的卡顿归因 |
| `tools/playtest.mjs` | 脚本化移动/射击冒烟测试 |

有两点发现值得记录，因为它们都否定了此前的测量结论：

**中位帧时间掩盖了真实问题。** 静态相机基准测得 94 fps，而游戏实际上卡到无法游玩。
在 Retina DPR（内部 3.34 MP，而非 2.07）下真实游戏只有 12–17 fps，伴随
**728–1236 ms 的停滞**，起因是 34+ 个 WebGL 程序在帧中懒编译。
`profile.mjs` 上报 p50/p95/p99 并逐项归因每次卡顿，正是它揭出了这个问题。

**截图此前不可复现。** `shotset.mjs` 在 11 个镜头间复用同一个页面，导致
粒子年龄、贴花缓冲和曝光状态向前泄漏——两次相同运行在 11 个镜头中有 10 个不一致。
`baseline.mjs` 将每个镜头隔离在全新页面中，做到了逐位一致，
这正是 `imagediff.mjs` 能作为门禁使用的前提。

## 性能

在 Apple silicon 笔记本、1512×982、DPR 2（内部 3.34 MP）、`ultra` 预设、
3 次运行、AI 与开火均处于活跃状态的游戏过程中测得：

| | 优化前 | 优化后 |
|---|---|---|
| fps p50 | 12–17 | **28–30** |
| fps p99 | 4–9 | **14–17** |
| 最差帧 | 728–1236 ms | **66–82 ms** |
| 游玩中的着色器编译 | 34–35 | **0** |
| 启动 | ~9–12 s | **3.7–4.6 s** |

优化过程被约束为**零视觉变化**，由 `imagediff.mjs` 而非断言来强制保证——
最终交付的构建与其优化前的参照在全部 11 个镜头上逐位一致。

着色器预热（`src/core/prewarm.js`）消除了停滞。要把它做到*可证明的*像素中性，
首先需要修复那些基于 `performance.now()` 而非引擎时钟做动画的子系统，
因为启动时长的任何变化都会导致输出偏移。

## 诚实评估

目标是对标一款现代《使命召唤》。**它没有做到。**

十一位独立的对抗性评审按此标准打分。
得分从 3.59 → 4.14 → 4.05 → **5.05**（满分 10）。两个镜头达到「接近」；
其余仍停留在「业余」水平。在盲测 A/B 中，**每一轮每一位评审都选了真正的
《使命召唤》那一帧。**

具体差距在哪里：

- **手部。** 呆板的块状手指，没能令人信服地握住武器。
- **材质丰富度。** 近距离下表面读起来像程序化噪声而非照片级的真实——
  这就是用代码生成纹理的天花板。
- **角色。** 远处的敌人读起来像服装模特。
- **间接光照。** 只是近似，不是真正的全局光照。
- **帧率。** Retina 下 28–30 fps。美术环节使几何成本翻了三倍
  （5.9M → 11.3M 三角形），优化只收回了一半。

还有一个已知的根因未修复：`render/index.js` 中的第一人称视角灯光装置
向每单位反照率输送的辐照度大约是场景世界的 20 倍——视角场景中一块纯*黑色*
材质仅凭 F0=0.04 就渲染为 L=110，背景为 91。
每一件武器的反照率都被作弊压到物理值的三分之一来补偿，这又限制了游戏中
最受关注对象的材质分离度。

## 过程笔记

顺序单主通过式迭代完胜并行扇出。三轮各由六个代理分别拥有一目录的迭代
只把分数推高了 +0.46，而且把破坏帧率的缺陷弄得更严重了（60 → 47 → 66），
因为色调映射、天空和间接光照是同一个耦合系统，孤立的代理不断破坏彼此的前提。
一次由单一所有者逐项处理耦合关注点的顺序迭代，把它推高了 +1.00，
并将缺陷从 66 砍到 26。

最有价值的单个成果来自一个违背自身简报的代理。连续三轮，每一位评审都报告武器
「没有纹理」。事实并非如此——它是高光主导的，漫反射项实测 L=26，而发布版为 L=67。
此前的迭代一直在压低反照率来对抗亮部过曝的抱怨，这杀死了漫反射、让问题更糟。
修复方向与当初的要求恰好相反。
